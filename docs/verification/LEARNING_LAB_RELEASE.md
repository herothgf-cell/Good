# 학습 테스트 v0.7.0 검증 기록

## 검증 범위

기존 칭찬/일반 쿠폰/시간 쿠폰/뽑기 공개 설정을 유지하면서, 보호자만 접근하는 학습 테스트와 이후 명시적인 아이 공개 흐름을 추가합니다. 테스트는 독립된 체험 데이터로 수행하며 운영 가족의 별·쿠폰·학습 공개 상태를 변경하지 않습니다.

## 확인한 결과

- TypeScript 앱 및 Edge 타입 검사 통과.
- 데모 웹과 설치 없이 열 수 있는 `preview.html` 빌드 통과.
- 새 빌드의 Node 자동 검사 **362개 통과, 실패 0**.
- 영어/수학 각 3개 활동의 30문항에 대해 독립적인 정답·영문·그림 수량을 검사.
- 보호자 미리보기로 실제 별·쿠폰·칭찬·아이 완료 기록이 바뀌지 않음을 검사.
- 현재 콘텐츠를 끝까지 테스트하지 않은 활동의 공개, 아이/칭찬 가족의 위조 관리 요청, 잘못된 완료 데이터, 오래된 공개 버전의 완료 요청을 거절함을 검사.
- 기기 간 동일 완료 중복, 마지막 일일 횟수 경쟁, 보호자 동시 칭찬, 공개 중지와 완료/공개의 경쟁을 검사.
- 응답을 받지 못했을 때 같은 UUID/요청으로 결과를 회복하며 중복 지급하지 않음을 검사.
- 독립 검토에서 발견한 오래된 공개 확인의 덮어쓰기와 15개를 넘는 미확인 기록의 표시 누락을 수정하고 회귀 검사를 추가.
- 최종 빌드의 기존 화면 38개, 시간 쿠폰 13개, 학습 22개로 **브라우저 시나리오 73개 그룹 통과**. 360·390·768·1024px에서 실제 한국어·이모지 글꼴로 버튼과 가로 넘침을 확인하고 화면을 검토했습니다. 로컬 음성/빈 음성 목록/원격 음성만 있는 경우, 중지와 역할 전환, 보관 중인 60개 기록, 오래된 공개 확인창의 무효화도 포함합니다. 검사 중 마이크 사용·외부 요청·브라우저 실행 오류는 없었습니다.

로컬 Node 24의 전역 `navigator.locks`와 제한 환경의 조합은 기존 체험 저장소 테스트를 종료하지 못했습니다. 검증 시 `node --no-experimental-global-navigator --test --test-isolation=none tests/*.test.mjs`로 브라우저 전역을 끄고 기존 비브라우저 큐 경로를 사용했습니다. CI는 프로젝트가 사용해 온 Node 22에서 표준 `npm test`를 실행합니다. 브라우저의 실제 클릭 흐름은 별도 Playwright 검사에서 확인합니다.

- `family-action` 버전 8, ACTIVE, JWT 검증 유지. 배포 파일을 다시 읽어 런타임 의존 파일과 로컬 검증 소스가 일치함을 확인했습니다. 타입 선언 파일은 런타임 번들에서 제외됩니다.

- 실제 게시 주소의 ES 모듈도 새 브라우저에서 확인했습니다. 공유 로그인 화면 → 명시적 체험 모드 → 보호자 미공개 6개 활동 → 아이 메뉴 숨김까지 5개 시나리오를 통과했습니다. 모듈 응답은 모두 200/JavaScript MIME이었으며 실행 오류, Supabase API 요청, 외부 쓰기, 마이크 요청은 없었습니다. 이 환경의 HTTPS 프록시 인증서 예외를 격리된 검사 브라우저에 적용했으며, 별도 시스템 인증서 검증을 통한 HTTPS 자산 조회도 통과했습니다. 실제 보호자 로그인/거래 검사는 수행하지 않았습니다.
- 배포 전후 운영 DB를 읽기 전용으로 조회해 학습 공개 **0건**, 운영 가족 학습 상태의 신규 생성 **0건**을 확인했습니다. 실제 가족의 테스트·공개·칭찬 요청을 실행하지 않았습니다.

이후 문서만 갱신한 커밋은 위 런타임 파일을 변경하지 않습니다. 최신 자동 실행 상태는 Actions에서 확인할 수 있습니다.
