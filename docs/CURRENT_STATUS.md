# 현재 개발 상태 — v0.5.1 뽑기 공개 설정

- 연준이 메뉴에서 뽑기를 기본 숨김. 신규 가족과 공개 설정이 없는 기존 가족 모두 적용.
- 보호자 설정과 보상 → 뽑기 설정에서 `연준이에게 뽑기 공개` 스위치로 즉시 저장.
- 공유 상태 `gachaEnabled`는 `true`일 때만 공개. 보호자만 변경 가능하며 숨김 상태의 실제 뽑기는 서버에서도 거절.
- 설정 변경은 기존 가족 갱신 흐름으로 기기 간 공유. 열려 있던 아이 뽑기 화면/미확정 확인창도 숨김 반영 시 닫음.
- 전환 시 상자 버전을 올려 이전 공개 기간의 뽑기 확인을 무효화. 이미 완료된 거래의 영수증 재조회는 유지.
- 별·보상 재고·쿠폰·칭찬 기록을 초기화하지 않으며 DB 스키마 변경이 필요하지 않음.
- 자세한 사용법: `docs/technical/FAMILY_EXPERIENCE_V05.md`.

# 현재 개발 상태 — v0.3 보호자 기능 (2026-10-27)

## 기능

- 보호자: 우리 가족에서 구성원의 표시 이름 수정. 로그인 계정/권한/기존 거래는 유지.
- 보호자: 칭찬 붙여주기 화면의 별 직접 지급. 수량 1~10,000 정수, 사유 및 최종 확인 필수.
- 보호자: 보상 만들기에서 등록 보상 직접 지급. 별 차감 없이 쿠폰 1장 발급, 유한 재고 1개 소진.
- 보관함에 보호자 선물·지급자·사유 표시. 기존 사용 요청/승인/사용 완료 유지.
- 일반 칭찬은 1~3개 유지. 직접 별 지급은 칭찬 횟수를 늘리지 않으며 별 원장/누적별에 기록.
- 요청 재시도는 기존 영수증을 반환하여 중복 지급 방지.

## 배포 구성

- Supabase good-praise의 family-action v3 적용. 공유 규칙은 `02943cbf348e6fe0f9fa77d23ab1ad9e4af4d060` 커밋에 고정.
- DB migration `20261027022544_guardian_member_rename.sql` 적용.
- Pages는 main push의 Verify Praise Star 성공 후 해당 검증 커밋을 cloud 모드로 자동 배포. 수동 cloud/demo 배포도 유지.
- 실제 웹 배포 성공 여부는 해당 커밋의 Actions 실행에서 확인. 서버 규칙 변경은 main 반영만으로 적용되지 않으며 Edge 재배포 필요.
- 구버전 앱 표시가 남으면 브라우저 새로고침/앱 닫고 다시 열기. 브라우저 데이터 삭제는 아이 기기 연결을 잃을 수 있으므로 권하지 않음.

## 검증

- 로컬 TypeScript / 빌드 및 자동 검사 130개 통과.
- Chromium PC·360px·390px 화면: 기존 13개 + 신규 9개 시나리오 그룹 통과.
- 실제 DB 롤백 트랜잭션: 이름 변경, 동일 요청 재전송, 다른 요청 내용 거절, 오래된 이름 거절, 공백 이름 거절, 외부 구성원 거절 확인. 검증용 변경은 남기지 않음.
- CI의 빈 PostgreSQL DB 테스트에 이름 수정 권한 및 재전송 검사를 추가. 운영 DB에서 tests/db_test.py를 실행하면 안 됨.
- 실제 사용자 요청에 따른 1회 초기 적립과 이름 정정만 운영 데이터에 기록. 테스트 보상을 지급하지 않음.
- 보호자 비밀번호 없이 자동검사를 수행했으므로 실제 가족 휴대폰에서 버튼 입력부터 인증 거래·화면 동기화까지의 전체 흐름은 별도 현장 확인 필요.

기존 범위/제한: 가족당 아이 1명, 텍스트·이모지 보상, 15초 갱신, JSON/CSV 내보내기. 사진·QR·알림·천장·백업 복원 UI 및 CAPTCHA는 후속 범위.
