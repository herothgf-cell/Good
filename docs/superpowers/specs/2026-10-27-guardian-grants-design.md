# 보호자 직접 지급 및 이름 수정

사용자 요청: 초대 이름 엄→엄마 정정, 보호자 보상 직접 지급, 별 직접 지급, 연준이 초기 별 13개 지급.

## 결정과 범위
기존 TypeScript 정적 PWA / Supabase를 유지한다. DB 수동 정정만 하는 임시안 대신, 앱에서 반복 사용 가능한 기능을 구현한다. 보상 직접 지급은 별 0개 차감, 등록한 공개 보상 1장/요청, 유한 재고 1개 소진이며 사용 승인 흐름은 동일하다. 별 직접 지급은 보호자만 1~10,000 정수와 사유를 입력한다. 일반 칭찬은 기존 1~3개를 유지한다. 모든 지급은 원장/요청 번호에 기록하고 재시도는 같은 결과를 반환한다.

이름 수정은 보호자가 같은 가족 구성원의 표시 이름을 1~30자로 변경한다. 이메일/비밀번호/권한은 변경하지 않고 기존 거래 당시 이름은 보존한다. 경쟁하는 이름 수정은 이전 이름 확인으로 덮어쓰기 방지한다.

초기 13개는 현재 연준이 가족에 1회 +13으로 기록한다. 앱 실행/신규 가족 기본값을 13으로 바꾸지 않는다. 실제 데이터에 테스트 보상을 넣지 않는다. 무료 범위 이외 리소스 생성, 인증 우회, 비밀 키 공개 없음.

## 화면
우리 가족: 구성원별 이름 수정 버튼. 칭찬 붙여주기: 별 직접 지급 버튼. 보상 만들기: 보상별 직접 지급 버튼. 보관함: 보호자 선물 표시 및 지급자/사유. 모든 지급에 최종 확인.

## 검증
순수 규칙/권한/중복요청/재고·경쟁 요청/입력검증, 브라우저 흐름, SQL 권한과 이름 수정 검증, 빌드 및 배포 확인. 실제 사용자 비밀번호는 요청하지 않는다.
