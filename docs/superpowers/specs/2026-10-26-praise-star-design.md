# 칭찬 별나라 v0.1 승인 기획 및 구현 결정

2026-10-26 대화에서 사용자가 전용 웹앱, 가족 공동 지급, 확정 보상과 가챠 병행, 부모의 보상 설계를 승인하고 개발을 요청했다.

## 목표
가족이 칭찬을 지급하면 아이가 별을 확인하고, 확정 교환 또는 꽝 없는 뽑기로 쿠폰을 얻고, 보호자가 실제 사용을 승인한다. 휴대폰과 PC를 모두 지원한다.

## 확정 범위
- 초대받은 가족만 접근. 관리자/칭찬 지급자/아이 권한 분리.
- 칭찬 1~3개, 사유/지급자/시간 원장. 오류 정정만 허용, 벌점/현금/광고 없음.
- 보상 CRUD, 상점 가격, 유한/무한 재고, 상점/가챠 노출.
- 뽑기 비용 기본 5, 하루 3회, 확률 합 100%, 재고 소진 시 실제 확률 재계산·사전 공개.
- 상자 조건이 바뀐 경우 재확인. 잔액과 재고/쿠폰 지급은 한 거래. 중복 요청 식별.
- 쿠폰: available → requested → approved → used. 거절은 available로 복귀(별 재차감 없음).
- JSON/CSV 내보내기. 작은 화면/키보드 접근/동작 줄이기 대응.

## 접근 비교와 구현 결정
승인된 초안은 Next.js + Supabase + Vercel이다. 서비스의 모든 핵심 동작은 클라이언트 UI와 인증된 Supabase 거래로 가능하므로 SSR이 필요하지 않다.
구현자 결정: 1차는 **TypeScript 정적 PWA + Supabase Edge Function/Postgres + Vercel 정적 배포**로 단순화한다. Next.js와 React를 설치하지 않아도 체험판을 열 수 있고, 서버 원가/런타임 의존성을 줄인다. 이 결정은 사용자가 프레임워크 변경을 따로 지시한 것이 아니다. 이후 필요 시 UI를 Next.js로 이식할 수 있다.
현재 작업 환경에서 npm 레지스트리 DNS 접근이 되지 않는 것도 제약이다. 설치되어 있는 TypeScript 5.8.3과 Node의 내장 테스트로 검증하며, 라이브 서비스 연결을 거짓으로 주장하지 않는다.

## 저장 구조
가정용 MVP는 가족 상태 JSONB 1행(별 원장/칭찬/보상/쿠폰)을 revision CAS로 원자적으로 갱신한다. 가족 구성원과 초대, 불변 명령 감사 기록은 별도 테이블이다. 서버/체험판은 동일한 순수 TypeScript 업무 규칙을 사용한다. 규모가 커지면 원장을 정규화한다. 전체 상태를 내려받으므로 대규모 서비스용 설계는 아니다.
클라우드는 브라우저에서 상태를 직접 쓸 수 없다. Edge Function이 사용자 토큰을 검증하고 실제 멤버 권한을 읽어 명령을 실행한 후 service_role 전용 commit RPC에 전달한다. commit은 멤버 권한 재검사, 행잠금, revision 검사, request_id 중복 검사를 한다. 서비스 키는 서버 환경변수에만 있다.

## 로그인
성인은 Supabase에서 생성한 이메일/비밀번호 계정으로 로그인한다. 가족 초대 코드는 가입 승인용이지 비밀번호가 아니다. 아이는 익명 인증을 사용해 보호자가 발급한 일회용 아이 초대로 기기를 연결한다. 공개 회원가입/메일 발송/Google 로그인은 v0.1에서 제외한다. 초기 관리자 계정 및 가족 성인 계정 생성은 Supabase 대시보드에서 수행한다.

## 제외 및 실제 연결 전 조건
실서비스 배포, 계정 생성, 프로젝트 생성은 현재 연결 권한 없이 완료했다고 표시하지 않는다. 체험판은 브라우저별 저장이며 다른 기기와 공유되지 않는다. 역할 전환은 체험판에만 있고 보안장치가 아니다.
천장/캐릭터 성장/주간 미션/사진 업로드/주간 보상 제한/복수 아이/실시간 소켓은 다음 버전. 가족 공유는 15초 polling + 창 활성화 시 새로고침으로 구현하며 실제 즉시 동기화라고 부르지 않는다.
